Missing pixel annotations or state examples alone are not open decisions. The intake archive is a source record, never a direct specification amendment or production-code authority.

## Source inventory and asset disposition

- `docs/theme-system/ASSET_MANIFEST.json` lists **117** project files: design references, six catalog JSON files, and staged candidates. SHA-256 audit: **117/117 match**; see cycle evidence `source-hash-audit.txt`. The five theme phone crops, available Atmospheric/Glass/Minimal OLED/Instrument/Terminal backdrops, Glass and Instrument boards/crops, shared package crops, icons, and all candidate catalogs were inventoried. Their paths are recorded in the manifest. No reference is copied into Android runtime resources by this slice.
- `oxygenwx-theme-pack-governed-intake.zip` contains `MANIFEST.sha256` with **131 file records; 131/131 match** by reading entries in place. Its `README.md`, `proposals/SPECIFICATION_AMENDMENT.md`, `proposals/UI_SPEC_AMENDMENT.md`, and `prompts/00_REVIEW_GOVERNANCE.md` were reviewed without extracting over repository files. The archive was prepared against `7e63abad6344f8c1d82e6bfd71590782af9c23a1`; its old governance proposal describes obsolete pre-adoption theme names. Current specifications already adopt the five-theme family, so that proposal does not supersede them.
- `docs/theme-system/staged-production/` and cycle-024 worktree files are quarantined implementation candidates. They are **not** cited as production authority or accepted design output. The source inventory also includes current presentation models and `DemoWeatherRepository.kt`; its 72-hour/10-day fixture is test content, not permission to fill sparse forecasts.
- Full boards and crops remain design references. SVGs/icons may be adapted later only after semantic fit, asset licensing, and visual acceptance are checked. Reference-only gauges/charts require explicit typed data contracts and are excluded from this pack. Backgrounds cannot be pasted as full UI screenshots; decorative treatments must preserve Effects Off.

## Design review decisions

1. TP.1B/C calculate and record proposed values for color/opacity/spacing/radius, typography, shell geometry, status/action treatments, and responsive behavior using the measurement method. Resolve Glass 26 dp against its board scale through a documented measured choice. Specify High contrast pairs from semantic roles and verify legibility.
2. TP.1B/C derive theme-specific marks/backdrops and Effects Off treatments from the references and existing model/effects contract. Resolve requested Full on themes with `supportsFull: false` through the effective appearance rule without changing saved preference or weather meaning.
3. TP.1D reviews measured values in integrated renders for all 20 theme/page cells and responsive states. Revise the codifiable values where render comparison shows a mismatch, then record explicit owner approval of the finished pack before TP.2.

A source conflict requiring a product-semantic change must be escalated to
`docs/SPECIFICATION.md` or `docs/OXYGEN_UI_SPECIFICATION_ADOPTED.md` by an
owner-directed later cycle. The current user-directed clarification to the
adopted UI specification changes visual derivation only, not product meaning.
